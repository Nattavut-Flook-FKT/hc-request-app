Firestore — hc_requests/{id}
  • status: newStatus
  • statusHistory: arrayUnion({ status, changedAt, changedBy, changedByName })
  • ──── กฎพิเศษเพิ่มเติม ────
  • ถ้า request ยังไม่มี TA + status ใหม่ไม่ใช่ Open → assignedTo/Name/At = TA คนนี้ (auto-assign)
  • newStatus = "Rejected" → เพิ่ม rejectedAt: serverTimestamp()
  • newStatus = "Closed" → เพิ่ม closedAt: serverTimestamp()
  • newStatus = "Onboarding" → ล้าง rejectReason, rejectedAt
  • newStatus = "Offering" (และยังไม่มี offeringDate) → เพิ่ม offeringDate: now
  • กลับไป Open/Recruiting/Interviewing → ล้าง offeringDate
  • กลับไปก่อน Onboarding → ล้าง candidateName, startDate
↓
GAS — updateStatus
  • GET ?action=updateStatus&id={docId}&status={new}&hcId={hcId}&secret=XXX
  • GAS map status → ชื่อ Sheets: Recruiting → "Active Sourcing", Offering → "Pending Offer", Onboarding → "Pending Onboard", Closed → "Onboard", Rejected → "Turndown", Cancelled → "Job Cancelled"
  • มี debounce 800ms — ถ้ากด status ซ้ำเร็วๆ จะส่งแค่ครั้งสุดท้าย
↓
Audit Log — hc_logs
  • action: "StatusChange"
  • fromStatus → toStatus
  • note: วันเริ่มงาน/ชื่อ candidate ถ้ามี

SLA — กลไกนับวันเปิด Request
ฟังก์ชัน getDaysOpen(req) ใน RequestTable.jsx — กฎครบ 3 ข้อ
▶️ นับปกติ
Open/Recruiting/Interviewing
⏸️ PAUSE
Offering/Onboarding
🔄 RESET
Onboarding→Recruiting
⏹️ หยุด
Closed/Cancelled
กรณี กฎ ผลลัพธ์
Open → Recruiting → Interviewing นับปกติตั้งแต่ createdAt days = วันที่ผ่านมา
→ Offering accumulated += (เวลา Offering - activeStart); activeStart = null ⏸️ หยุดนับ — badge สีเทา
Offering → Interviewing (reject offer) activeStart = t (Interviewing) — นับต่อจากเดิม ▶️ Resume ต่อจากที่ค้างไว้
→ Onboarding accumulated += ...; lastPauseWasOnboarding = true ⏸️ หยุดนับ + mark flag
Onboarding → Recruiting (reject onboard) lastPauseWasOnboarding = true → accumulated = 0; activeStart = t 🔄 รีเซ็ต 0 วัน เริ่มใหม่
→ Closed หรือ Cancelled accumulated += ...; activeStart = null ⏹️ หยุดถาวร แสดง X days (gray)

สีของ SLA Badge

🟢 12d น้อยกว่า 15 วัน — ปกติ
🟡 22d 15–30 วัน — ควรเร่ง
🔴 45d มากกว่า 30 วัน — เกิน SLA
⏸ 8d Paused (Offering/Onboarding)

Realtime & Page Visibility
ระบบทำงานอย่างไรเบื้องหลัง — เพื่อประหยัด Firestore reads

🔴 onSnapshot — Realtime Listener

ตาราง request ดึงข้อมูลจาก Firestore ด้วย onSnapshot() — ทุกครั้งที่ใครในทีมแก้ไข request ข้อมูลจะ update ในหน้าของทุกคนทันที โดยไม่ต้อง refresh

Query
  • collection("hc_requests") → orderBy("createdAt", "desc") → limit(500)
  • ดึงสูงสุด 500 records ล่าสุด

👁️ Page Visibility API — ประหยัด reads

เมื่อ tab ถูกซ่อน (เปิด tab อื่น / minimize) → listener จะหยุดทำงาน
เมื่อกลับมา tab นี้ → listener จะเริ่มใหม่ และดึงข้อมูลล่าสุดมาทันที

💡 ทำไมต้องทำ: Firestore คิดค่าตาม reads — ถ้า listener ทำงานตลอดแม้ไม่ได้ดู จะเปลือง quota โดยใช่เหตุ

📡 GAS Debounce 800ms

เมื่อ TA เปลี่ยน status หลายครั้งเร็วๆ (เช่น ลืมกด กด 2 ครั้ง) — ระบบจะ ยกเลิก call เก่า และส่งแค่ครั้งสุดท้ายไป GAS หลังจากหยุดกด 800ms เพื่อป้องกัน spam request
